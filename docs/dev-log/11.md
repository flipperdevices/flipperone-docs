## Modular M.2 Radios: Independent Cellular & GNSS Control

Flipper One includes an **M.2 Key-B expansion slot** on the back. Designed for high-speed add-on cards, it lets you plug in 4G/5G cellular modems, GNSS/GPS navigation modules, or custom radio boards directly into the high-speed bus.

![2. Section 1: Modular M.2 Radios (Technical Architecture Diagram)](/files/pics/dev-log/11/m2-rfkill-diagram.jpg)

When integrating WWAN cards from vendors like Quectel, Fibocom, and SIMCom, we ran into an unexpected software conflict in Linux's `rfkill` subsystem.

### The Problem: When disabling GPS kills your mobile data

Standard M.2 Key-B cards feature two dedicated hardware disable pins:
- **Pin 8 (`W_DISABLE1#`)**: Disables the cellular (WWAN) transceiver.
- **Pin 26 (`W_DISABLE2#`)**: Disables the GNSS/GPS receiver.

In early device tree configurations, both switches were registered under the generic `rfkill` type `wwan`. Because Linux's `NetworkManager` monitors all `wwan` rfkill nodes as master cellular killswitches, running a command to shut down GPS (`rfkill block 1`) caused NetworkManager to immediately log:

```text
NetworkManager[482]: <info> [1729512340.12] rfkill: WWAN now disabled by radio killswitch
NetworkManager[482]: <info> [1729512340.14] device (cdc-wdm0): state change: activated -> unavailable
```

Even though the modem hardware kept its LTE connection alive, userspace disconnected the interface.

### The Fix: Mainline GPS registration

Pavel Zhovner (`zhovner`) submitted and merged a fix into our Linux kernel tree ([flipper-linux-kernel#26](https://github.com/flipperdevices/flipper-linux-kernel/pull/26)):

```dts
/* Map M.2 Pin 26 (W_DISABLE2#) explicitly as a GPS rfkill device */
wdisable2_rfkill: rfkill-gps {
    compatible = "rfkill-gpio";
    label = "M.2 GNSS (WDISABLE2)";
    radio-type = "gps";
    shutdown-gpios = <&gpio1 RK_PC2 GPIO_ACTIVE_LOW>;
};
```

Because `NetworkManager` only manages `wlan` and `wwan` switches while intentionally ignoring `gps`, disabling GPS via software now operates completely independently of mobile data:

```bash
# Disable GPS only without interrupting active LTE data:
rfkill block gps

# Turn off cellular data only:
rfkill block wwan

# Full radio silence:
rfkill block all
```

We are also prototyping an M.2 power-down device tree overlay (`flipper-linux-kernel#25`) that cuts the 3.3V power rail (`vcc3v3_m2`) and clamps all interface lines (`PWREN`, `RESET#`, `PERST#`, `W_DISABLE1/2#`) low to prevent parasitic powering when an M.2 module is unused.

## Under the Hood of the RP2350: Display Diagnostics, Touch & Haptics

While the Rockchip RK3576 runs Linux, the **Raspberry Pi RP2350** co-processor handles the real-time hardware: the display, buttons, capacitive touch, status LEDs, and haptics.

![3. Section 2: Under the Hood of the RP2350 (Video Storyboard)](/files/pics/dev-log/11/rp2350-display-touch-test.jpg)

As fresh PCB revisions come off the assembly line, our MCU firmware team (`Skorpionm`, `lomalkin`) landed a dedicated hardware diagnostics suite directly in firmware:

1. **Display Test Application ([flipperone-mcu-firmware#269](https://github.com/flipperdevices/flipperone-mcu-firmware/pull/269))**:
   - Launches via physical button shortcuts (`SW` button).
   - Cycles through alternating subpixel grids, solid color fields (Red, Green, Blue, White, Black), and 1-pixel checkerboard patterns using the Left/Right and PTT buttons to catch dead pixels or flex cable signal integrity issues instantly.
2. **Capacitive Touch V2 & Haptics ([flipperone-mcu-firmware#260](https://github.com/flipperdevices/flipperone-mcu-firmware/pull/260))**:
   - Live coordinates and gesture tracking for the front touch sensor.
   - Frequency and duration calibration for the haptic motor to deliver crisp tactile feedback when navigating FlipCTL menus.

## Seamless Profile Hopping: Unified Device Identity

In [Dev Log #10](./10.md), we introduced Flipper OS profiles (Minimal, No Graphics, Desktop, TV Media Box, and Router), allowing developers to reboot into entirely different Linux personalities.

![4. Section 3: Seamless Profile Hopping (Architecture Infographic)](/files/pics/dev-log/11/btrfs-sync-identity-diagram.jpg)

However, testers running headless SBCs ran into an immediate annoyance: **every profile generated its own SSH host key**.

When you switched from your Debian Desktop profile to the Router profile, SSH clients on your laptop immediately aborted the connection with a scary security warning:

```text
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
Host key for 192.168.1.105 has changed and you have requested strict checking.
```

### The Solution: `flipper-sync-identity`

To solve this, contributor `rafaetri` built a profile identity synchronization service ([flipperos-btrfs-tools#2](https://github.com/flipperdevices/flipperos-btrfs-tools/pull/2) & [flipperone-linux-build-scripts#184](https://github.com/flipperdevices/flipperone-linux-build-scripts/pull/184)):

- A single master set of SSH host keys is persisted in a protected directory on the shared boot subvolume: `/boot/flipper-identity/`.
- A lightweight systemd unit (`flipper-sync-identity.service`) runs early in the boot sequence before `ssh.service`.
- When booting any profile, the service verifies and seeds `/etc/ssh/` with the device's persistent host keys.
- During initial device onboarding or manual updates, `sync-identity --push` propagates keys across all profile root subvolumes simultaneously.

Now, you can hop between Desktop, Router, and Minimal profiles as often as you want, and your SSH sessions and tooling will reconnect seamlessly.

## Live Power Meter & Kickstarter Demo Suite

The built-in **Power Meter** on Flipper One displays real-time battery charge/discharge rates, USB-PD negotiated voltages, and peripheral power draw.

![5. Section 4: Live Power Meter & Kickstarter Demo](/files/pics/dev-log/11/power-meter-spikes-demo.jpg)

In the `flipperone-testing` repository, Vlad Petrenko added several updates to the Power Meter test harness:
- **Live Transient Spike Detection**: Captures rapid sub-millisecond inrush currents when external GPIO or M.2 modules power on.
- **Dynamic Brightness & Contrast Calibration**: Adjusts OLED curve levels based on ambient bus voltage.
- **Kickstarter Interactive Demo Mode**: A pre-configured sequence cycling through charging curves, sleep states, and peak load tests designed specifically for upcoming public demonstrations.

You can test how the Power Meter responds under simulated load right in your browser using our [interactive Power Meter emulator](https://dev.repetren.com/power_meter_demo/).

## Mainline Upstreaming: How the Community is Shaping Flipper One

We build Flipper One with an **upstream-first** approach: rather than maintaining fragile downstream vendor forks, our team works to mainline Rockchip RK3576 support directly into official Linux and U-Boot releases.

To help community contributors submit code directly to the Linux kernel and U-Boot mailing lists, contributor `hypery11` added a comprehensive [Upstreaming Guide](../cpu-software/rk3576-mainlining.md#how-to-contribute) to our developer documentation ([flipperone-docs#448](https://github.com/flipperdevices/flipperone-docs/pull/448)).

The guide covers:
- Using modern kernel tools like `b4` for formatting and sending patch series.
- Running `dtbs_check` against `dt-schema` before submitting device tree bindings.
- Validating self-contained commits that each build cleanly without breaking `git bisect`.
