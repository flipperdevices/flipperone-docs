## New PCB revision assembled

We've released the Flipper One PCB revision 2.F0B1C2. 

Check out the photo from the factory where the new Main PCBs were assembled:

![A panel of new Main PCB reviewed after assembly](/files/pics/dev-log/6/printed-boards.jpeg "A panel of new Main PCB reviewed after assembly")

The new PCB revision fixes a number of problems found since the previous release and includes the new haptic motor and eSIM chip, improved battery connector, changes for the microSD slot, and all the other features we mentioned in our DevLogs.

## Developer kit and 10-inch rack unit

When the PCBs and other components arrive in our lab, we assemble them into developer kits. Such kits securely hold the parts together and allow our engineers access each board from either side.

On the photo you can see Flipper One assembled: both the Control and Main PCBs, battery pack, and a [Flipper One debug probe](../hardware/Debug-probe.md) connected: 

![Flipper One developer kit](/files/pics/dev-log/6/flipper-one-dev-kit.jpg "Flipper One developer kit")

We've also designed a 10-inch rack unit that exposes all the ports on the front panel. In the future, we'll use rack units to build a device farm for automated testing of Flipper One.

![Flipper One rack unit](/files/pics/dev-log/6/flipper-one-rack-unit.jpg "Flipper One rack unit")

We know a lot of you would like to get a prototype into your own hands. We don't have a community testing program at the moment, but if and when that changes, you'll read about it in our Dev Log. [Subscribe](./Dev-Log.md#subscribe-to-dev-log) so you don't miss the news.

## Flipper OS profiles prototype

We're working on OS profiles, which are standalone system setups specialized for different tasks. You may have already seen two examples: the TV Media Box and Wi-Fi Router boot targets. Those are all OS profiles.

Here's the U-Boot boot menu running on a real Flipper One, listing the built-in OS profiles with two kernel versions each.

![U-Boot boot menu on Flipper One](/files/pics/dev-log/6/boot-menu.jpeg "Boot menu listing the OS profiles available to boot in")

While you use an OS profile, you can save its current state at any time, then return to this saved state or make it a new entry in the boot menu. For example, "Travel router stable" and "Lab before update" are derived from the same "Router" OS profile, just at different points in time.

![Flipper OS profiles: how stock snapshots, backup snapshots, and boot menu profiles relate to each other](/files/pics/dev-log/6/flipperos-profiles-concept.png)

Users are shared between OS profiles, so you won't have to create a user and password for each profile. At the same time, sharing users is a technical challenge which we'll tell you about in a future Dev Log.

Learn more from the docs: [OS profiles](../cpu-software/profiles.md).

## Multifunctional device on the USB-C1 port

When you connect Flipper One to a PC over the USB-C1 port, it can now show up as a composite device including:

- A virtual LAN adapter to Flipper One.
- A virtual serial port (CDC-ACM).
- A mass storage device — empty by default and can be used to mount an SD card or other storage.
- An MTP (Media Transfer Protocol) device sharing the `/home` directory.

![Windows File Explorer browsing the Flipper One home directory over MTP](/files/pics/dev-log/6/home-directory-mtp-shared.jpg "Browsing /home/user on Flipper One from a PC, over MTP")

For more details, see [flipperone-linux-build-scripts#133](https://github.com/flipperdevices/flipperone-linux-build-scripts/pull/133).

## Flipper OS installer

We made a new [Flipper OS installer tool](https://github.com/flipperdevices/flipperos-installer) available directly in the boot menu. Before, we had to install Flipper OS over USB using the rockUSB tool or write an OS image to the microSD card.

The new installer allows selecting the U-boot and OS versions, and which OS profiles to install:

## U-Boot menu upstream progress

At Flipper Devices, we strive to push our changes upstream and use unpatched mainline software whenever possible.

In Dev Log #4, we showed our custom boot menu running directly on the Flipper One screen. A few weeks ago, [mainline U-Boot gained support for generic directory listing on Btrfs filesystems](
https://lore.kernel.org/u-boot/178372904690.2905849.8798963092987519032.b4-ty@konsulko.com/T/#t), which is a prerequisite for upstreaming our boot menu changes.

## USB3 regression on RK3576 fixed upstream

After a recent kernel update, we found that USB had stopped working on our RK3576 SoC. We tracked the regression down to an upstream refactoring of the spread-spectrum programming in the Naneng combo PHY, merged during the Linux 7.2 merge window, which broke the USB3 link on RK3576.

We fixed it, and [the fix has been accepted upstream](https://lore.kernel.org/linux-rockchip/178454738244.1375859.4122685311138244257.b4-ty@kernel.org/).
